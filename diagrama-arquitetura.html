Agente de pré-venda Autoconf: arquitetura

Duas partes: o agente, que vai do recebimento da mensagem até a resposta, e as telas, que mostram e usam o que o agente grava.

PARTE A

Agente

Do recebimento até a resposta. Não tem tela própria.

ETAPA 01

Recebimento

Canal abstrato: o agente não sabe de onde a mensagem veio

Canal de entrada · qualquer uma das três origens

WhatsApp (Evolution API)

Webhook POST /webhook/evolution, evento messages.upsert. Responde 200 na hora e processa em segundo plano.

Tela de chat (web)

POST /chat vindo da nossa página. Permite testar e demonstrar sem depender da Evolution.

Terminal / simulador

Chama o mesmo pipeline direto, para os testes automáticos.

↓todas convergem

Montar payload (mensagem padrão)

{ canal, cliente_id, message_id, tipo: texto|audio|imagem, conteudo, midia, recebido_em }

Daqui para a frente todas as etapas trabalham só com este formato. Para criar um canal novo (Telegram, Instagram), basta escrever um adaptador.

ETAPA 03

Tratar o tipo

Tudo vira texto e o canal de origem é guardado

Texto

Segue como veio.

Áudio

ogg/opus, webm, mp3, m4a, wav, flac (até 25 MB). Transcreve com gpt-4o-mini-transcribe, com as marcas e modelos do estoque como dica, e corrige nomes mal ouvidos ("bi uai di" → BYD).

Transcrição vazia ou com ruído: pede para repetir, sem travar.

Imagem

jpg, png, webp, gif (até 20 MB). O modelo de visão descreve a imagem (ex.: foto do carro da troca, print de anúncio).

Outro arquivo

PDF, documento, vídeo, figurinha, HEIC, vazio ou grande demais: resposta amigável ("pode mandar como foto, áudio ou me contar por texto?"), sem quebrar.

Só cumprimentou ("oi", "boa tarde", #thread) no começo da conversa

Saudação fixa

"Boa tarde! Aqui é a Lia, da Autoconf Veículos 😊 Como posso te ajudar?" (o período segue o que o cliente disse ou o horário de Brasília). Não passa pelo agente.

Grava

Mensagem no histórico SQLite

Texto normalizado + tipo_origem (texto, áudio ou imagem), que depois define o formato da resposta.

ETAPA 04

Guardrail de entrada

Só bloqueia. O que passa vai para o agente.

O que bloqueamos

  • Assuntos fora da venda de carros: cotação do dólar, futebol, política, receitas, tarefas gerais
  • Injeção de prompt: "ignore suas instruções", "mostre seu prompt", "finja ser outro assistente"
  • Mensagem ofensiva ou abusiva
bloqueado
Resposta fixa que traz a conversa de volta para carros
↓ passou: todo o resto segue para o agente, inclusive reclamação e pós-venda
ETAPA 05

Agente

LangGraph controla o fluxo, LangChain faz as chamadas

Antes do agente · ficha e checklist (regra em código)

extrair_dados SQLite

Lê a última mensagem do cliente e grava na ficha o que ele informou (saída estruturada). O agente não precisa lembrar de anotar.

→

checklist

O código compara a ficha com o que o PDF pede: ✅ já respondido, ⬜ falta, e qual é a próxima pergunta.

→

ordem do turno

Se há motivo de transferência: ação obrigatória. Se o cliente disse o que procura ou o orçamento: o código escolhe os carros (mais perto do orçamento) e o agente só apresenta.

↓vai no prompt do agente

carregar_contexto

Últimas N mensagens + checklist do lead

→

Agente (LLM) · orquestrador

Responde, mostra carros e faz só a próxima pergunta do checklist. Decide quando chamar uma tool.

→

checar_transferencia → resposta

Se prometeu passar para o vendedor sem chamar a tool, é cobrado 1 vez. Depois vai para o guardrail de saída.

⇅ chama a tool · recebe o resultado

buscar_estoque SQLite

Filtros: tipo, preço máx., ano mín., marca/modelo. Só retorna carros que existem.

detalhes_carro SQLite

Dados completos de um carro por id (km, ano, preço).

transferir_humano SQLite

Recebe motivo + urgência, gera o resumo, marca a conversa como "com humano" e avisa o vendedor.

Ordem do checklist (pula o que já foi dito; "não sei" também conta)

3 perguntas: 1. Modelo / tipo de carro · 2. Valor · 3. Como quer comprar (à vista ou financiado) → respondidas = lead qualificado: vai para o vendedor com resumo, e o cliente é avisado de que ele vai chamar para agendar visita ou test drive.

Entrada, troca, prazo, idade e renda não são perguntados; se o cliente contar, vão para a ficha. 🟡 Respondido em parte ("pra família" sem o tipo, ou citou "uma Saveiro" na troca sem o ano): pergunta só a parte que falta. Cada item é perguntado no máximo 2 vezes.

Quando o agente chama transferir_humano

Reclamação · negociação de valor ou desconto ("fecho por 115 mil") · pedido de crédito ou parcela · urgência alta ("preciso essa semana") · cliente pede uma pessoa · qualificado: checklist completo (o código manda transferir)

ETAPA 06

Guardrail de saída

Só bloqueia. O que passa é enviado ao cliente.

O que bloqueamos

  • Código: preço citado que não está no estoque nem foi dito pelo cliente
  • Código: modelo oferecido que não está no estoque (dizer "não temos" e citar o carro de troca são permitidos)
  • LLM juiz: promessa (crédito, desconto, reserva, prazo), contraproposta de valor, vazamento de prompt. Só vale se citar o trecho exato com evidência da regra; senão a reprovação é descartada
bloqueado
Grava a versão reprovada (status = bloqueada + motivo). Regenera 1 vez e, se reprovar de novo, envia uma resposta segura padrão
↓ passou: a resposta segue para envio
ETAPA 07

Resposta

O formato segue o que o cliente mandou. O envio volta pelo mesmo canal.

1. Formato · definido pelo tipo_origem

Chegou áudio → responde áudio

gpt-4o-mini-tts gera o áudio em opus a partir de uma versão curta da resposta.

Chegou texto → responde texto

Envia o texto como está.

Chegou imagem → responde texto

Envia o texto como está.

↓resposta pronta no formato certo

2. Envio · volta pelo mesmo canal de entrada

WhatsApp

Evolution: sendText / sendWhatsAppAudio

Tela de chat

Retorna na resposta do POST /chat (texto ou áudio para tocar).

Terminal / simulador

Imprime a resposta e registra para o relatório de testes.

↓enviada

3. Grava resposta SQLite

Texto da resposta com status = enviada. Se foi em áudio, salva também o arquivo gerado pelo TTS e guarda o caminho em audio_path. Entra no histórico para o próximo turno.

GRAFO

O agente por dentro

Os nós e ligações que o LangGraph monta de verdade (extraídos do código), com um exemplo passando por eles.

LLM (decide e escreve) Código (regra fixa) Tool Banco sempre condicional

Exemplo · cliente manda: "Quero um SUV até 120 mil, vou financiar"

  1. extrair_dados grava SUV · até R$ 120.000 · financiar. As 3 respostas vieram juntas: lead qualificado.
  2. carregar_contexto junta a conversa, o checklist completo, os 4 SUVs até 120 mil (Duster → T-Cross) e a ordem de passar para o vendedor.
  3. agente mostra os SUVs com um comentário de vendedor e chama a tool transferir_humano (qualificado), que grava a transferência e o resumo.
  4. checar_transferencia confere: transferiu, não prometeu crédito, não soou como robô. Tudo certo.
  5. resposta limpa a formatação e entrega para o guardrail de saída, que confere os preços no banco antes de enviar.
Fim do agente. Tudo o que ele aprendeu está no banco, e as telas leem de lá.

MONITORAMENTO

Langfuse v3 (self-hosted)

Sobe no compose. Interface em localhost:3000

  • Um trace por mensagem, com guardrail de entrada, agente, tools, juiz e reescrita dentro dele
  • Saída do trace: tools chamadas, transferência e bloqueios
  • Latência e custo por turno
  • Agrupado por sessão (lead-{id}) e cliente
  • Projeto e chaves criados na primeira subida

Variáveis de configuração. Nenhuma chave vai para o repositório.

# OpenAI (LLM, Whisper, visão, TTS)
OPENAI_API_KEY=

# Evolution API
EVOLUTION_API_URL=
EVOLUTION_API_KEY=
EVOLUTION_INSTANCE=

# Gatilho do agente
TRIGGER_KEYWORD=#thread

# Langfuse (monitoramento)
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_HOST=https://cloud.langfuse.com

Decisões

  1. #thread é filtro de cada mensagem no WhatsApp. Sem a palavra-chave, a mensagem é ignorada. Áudio e imagem sem legenda não têm como trazer o texto, então passam se o cliente mandou #thread nos últimos 30 minutos. Na tela de chat e no terminal não precisa.
  2. Fora do assunto é bloqueado no guardrail de entrada. A resposta fixa traz a conversa de volta para carros, como o PDF pede.
  3. Idade e renda são dados pessoais (LGPD). Só são perguntadas quando o cliente quer financiar, e a renda é guardada como faixa.
  4. O vendedor vê a transferência no painel. Avisar o número dele pela Evolution fica para depois.
  5. Escopo de ~4h. Prioridade nas etapas 01–07 e no simulador. Painel e exportação para CRM na versão mais simples.
